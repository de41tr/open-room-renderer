# Release Checklist

Before publishing an alpha release:

- [ ] Neutral project name and positioning are used in public docs.
- [ ] Disclaimer is present.
- [ ] Alpha/experimental status is clear.
- [ ] No proprietary logos, icons, screenshots, app assets, audio assets, APK/IPA fragments, or firmware fragments.
- [ ] No copied app or firmware code.
- [ ] No decompiled-code excerpts.
- [ ] No private keys, certificates, cookies, tokens, service credentials, or real account metadata.
- [ ] No raw packet captures, raw protocol dumps, or unsanitized verbose logs.
- [ ] No real MAC addresses, serial numbers, device IDs, UUIDs, or private network IPs in public examples.
- [ ] No authentication, pairing, signature, DRM, encryption, certificate, or access-control bypass logic.
- [ ] Logs are sanitized by default and raw logging is clearly opt-in/private.
- [ ] Example configuration uses synthetic values only.
- [ ] Tests pass.
- [ ] Open-source client acceptance passes.
- [ ] Human legal review is recommended before public release.

This checklist is not legal advice.
