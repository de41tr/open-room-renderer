Experimental TIDAL login

This uses the regular python-tidal integration. Provider support and full playback are unverified. This local interface trusts your LAN; it does not authenticate other LAN users.

Starting asks TIDAL for a short-lived login challenge. Complete consent yourself on TIDAL's site. Credentials stay on this renderer. An existing session will not be replaced. This does not start playback. After login, a separate explicit action can share your account with trusted LAN controllers such as WiiM Home.

Refresh renews the existing account credentials once; it does not sign in another account or start audio. Same-account sharing stays enabled. An uncertain result must not be automatically retried.

Sharing exposes the access token and account identifiers through the existing device protocol to reachable LAN controllers, not only WiiM Home. The refresh token stays private. Sharing ends on renderer restart unless you select Remember before clicking Share. Remember saves this decision for this account; it does not start login or refresh. Token expiry suspends access; a verified same-account refresh renews the previous sharing decision. Stop account sharing removes both temporary and remembered sharing, including a suspended decision. It cannot recall access tokens already copied by an app or revoke provider grants. Native app re-login and full playback remain unverified.

To recover from rejected or uncertain refresh, forget the saved session, then start a new login. This removes only local credentials and account sharing. It does not delete your TIDAL account, revoke provider grants, or start a login. Cancel pending login and wait for it to finish; stop TIDAL playback first. Other playback is left alone. Native app logout is not supported.

This explicit test uses the private saved session; LAN account sharing is not required. It replaces the current queue and starts audio. Only unencrypted direct BTS audio is supported; MPD/DRM is unsupported. This explicit test may refresh an expired session once before requesting the track. There is no background refresh. A successful request is not proof of complete-track playback.
